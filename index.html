06 / Finding intelligence

Not just a finding.
The full picture.

Every issue answers what happened, why it matters, how confident we are and what to do next. Expand a sample finding to see the level of detail your team gets.

HIGHOWASP · A01:2021

Broken Access Control

GET /api/users/{id}

The application may not properly verify whether the authenticated user is authorized to access the requested resource.

Confidence 96%First seen Today
What happened?

A user-level resource request returned a response without a clear server-side ownership check.

Why does it matter?

An attacker could potentially access another user's information by changing a resource identifier.

How should I fix it?

Enforce authorization on the server for every protected resource. Compare the requested resource owner with the authenticated principal before returning data.

CRITICALOWASP · A03:2021

SQL Injection

POST /api/search

Input handling may allow untrusted values to influence a database query.

Confidence 91%First seen Today
What happened?

A controlled input variation changed the application's response pattern in a way that warrants developer review.

How should I fix it?

Use parameterized queries and strict input validation. Never build queries by concatenating request values.

HIGHOWASP · A03:2021

Stored Cross-Site Scripting

POST /comments

Untrusted content may be stored and rendered without sufficient output encoding.

Confidence 88%First seen Today
What happened?

User-controlled content appears to reach a rendered view without a confirmed safe encoding step.

How should I fix it?

Contextually encode output, sanitize rich content with a maintained allowlist and deploy a restrictive Content Security Policy.

MEDIUMOWASP · A05:2021

Missing Security Headers

HTTP example.com

Several browser security headers are not configured, reducing defense-in-depth for visitors.

Confidence 99%First seen Today
Why does it matter?

Headers such as HSTS and Content Security Policy make common browser-side attacks harder to execute.

How should I fix it?

Configure a tested CSP, HSTS, Referrer-Policy, Permissions-Policy and frame protection at the server or edge.

MEDIUMDEPENDENCY HEALTH

Outdated Dependency

PACKAGE ui-renderer@4.2.1

A package version appears behind a maintained release and should be reviewed against known advisories.

Confidence 84%First seen Today
What happened?

The assessed package manifest contains a version that does not meet the current project policy.

How should I fix it?

Review the advisory, upgrade within a tested range and lock the resolved version in the build.

LOWOWASP · A05:2021

Information Disclosure

GET /health

Response metadata may reveal implementation details that are not needed by a public health endpoint.

Confidence 78%First seen Today
How should I fix it?

Return only the minimum operational status needed by the caller and remove framework or version details from public responses.

14 / FAQ

Good questions
make better security.

Still curious? Our documentation goes deeper on scope, permissions and how assessments work.

Read the documentation ↗
What is BREACHAI?+

BREACHAI is an AI-powered security testing platform for websites and web applications. It maps an authorized application's attack surface, identifies potential vulnerabilities, safely validates findings where possible and turns them into prioritized developer guidance.

What websites can I scan?+

You can scan websites, web applications and APIs that you own or have explicit permission to assess. Add a project URL, choose its environment and confirm authorization before a scan begins.

Do I need permission to scan a website?+

Yes. You must own the target or have explicit authorization from its owner. Scanning third-party systems without permission is not allowed and may be unlawful.

Is BREACHAI a vulnerability scanner?+

It includes automated security testing, but the product is designed to go further: AI reasoning explains evidence, impact, confidence and remediation so teams can make informed decisions.

How does the AI identify vulnerabilities?+

The agent combines application discovery, controlled security tests, contextual analysis and safe validation. It does not treat every signal as a confirmed vulnerability; findings include evidence and a confidence level.

Can BREACHAI test APIs?+

Yes. API endpoints, authentication, authorization, input validation, rate limiting, error handling and excessive data exposure are part of the supported assessment areas.

Does BREACHAI exploit vulnerabilities?+

BREACHAI uses controlled, authorized validation where possible and avoids destructive actions. It does not provide unrestricted offensive capabilities, persistence, credential theft or malware deployment.

Can I download security reports?+

Yes. Reports can be downloaded as PDF or exported as JSON in the product experience. Evidence is safety-filtered so credentials, tokens and secrets are not reproduced.

Can I rescan after fixing an issue?+

Yes. Trigger a follow-up assessment after remediation, compare scores and keep the discovered, resolved and verified dates in your security timeline.

Does BREACHAI continuously monitor websites?+

Optional continuous monitoring supports scheduled assessments, dependency monitoring, new vulnerability alerts, regression detection and historical score tracking.

Is my website data stored?+

Scan data is handled according to your configured retention controls. The platform principle is data minimization, secure report storage and user-controlled deletion.

Can teams collaborate?+

Yes. Invite team members, assign roles, comment on findings, manage projects and share reports across Owner, Admin, Security Analyst, Developer and Viewer roles.
